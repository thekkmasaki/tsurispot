# 釣れる度（fish-aptitude）の方法論と出典

魚種ページ「釣れるスポット一覧」等の掲載可否・バッジ・並び順を決める
`src/lib/data/fish-aptitude/` の適性データの作り方を定義する。
全116魚種の適性データはこの方法論に従って作成・レビューする。

## スコア式（0〜100）

```
score = 地域適性×12 (0-48)   ← 支配項: 漁獲量統計・釣り実績
      + 地形適性×6  (0-24)   ← spotType との適合
      + 旬 8 / 出典 8         ← 補助シグナル（テンプレ汚染79%のため意図的に弱く）
      + rating×2.4 (0-12)    ← タイブレーク級
```

| tier | 条件 |
|---|---|
| ◎ excellent | score≥70 かつ 地域≥3 かつ 地形≥2 |
| ○ good | score≥45 |
| △ fair | 28≤score<45、または地域/地形いずれかが1（境界域の上限） |
| excluded | 地域0 or 地形0 or 両方1 or score<28 → 一覧・件数・sitemapから除外 |

## 地域適性レベル（0〜4）の判定基準

| レベル | 基準 |
|---|---|
| 4 特筆 | 県別漁獲量が全国上位（概ねトップ5〜8）または釣りのメッカとして定評（例: アオリイカの山陰・北陸・九州北西） |
| 3 好適 | 漁獲量・釣果実績が明確に厚い |
| 2 普通 | 全国的に釣れる魚のデフォルト |
| 1 まれ | 分布の北限・南限の境界域。釣れた記録はあるが安定しない（例: 山形・秋田のアオリイカ） |
| 0 生息せず | 分布外（例: 北海道のアオリイカ・タチウオ・マダイ、沖縄のメバル・スズキ） |

## 出典（優先順）

1. **農林水産省 海面漁業生産統計調査**（魚種別・都道府県別漁獲量）— レベル3/4の主根拠
2. **各県水産技術センター・水産振興資料** — 分布北限/南限・資源状況
3. **釣り実績**（釣具店釣果情報・釣果情報サイト・釣り媒体の定評）— 岸釣り観点の補正
4. 魚類図鑑的な分布情報（日本産魚類検索等の一般知識）— レベル0/1の判定

各魚種の `rationale` に要約を、`sources` に使った出典区分を必ず記載する
（`fish-aptitude.test.ts` が rationale 非空を検証）。

## 地理解決の優先順位

```
1. 湾・灘の狭域指定（seaOverrides の湾名。例: アオリイカの東京湾=1、マダイの陸奥湾=3）
2. 県指定（prefectureOverrides。数値 or 大分類海域ごとの分解 例: 兵庫 {日本海:4, 瀬戸内海:2}）
3. 大分類海域（seaOverrides の 日本海/太平洋/瀬戸内海/東シナ海/オホーツク海）
4. 8地域（regionOverrides。分布の北限南限を粗く書く用）
5. default
```

- 2海域に面する県（兵庫・山口・福岡・佐賀・青森等）は県レベルの数値を書かず、
  海域分解 `{ 日本海: x, 瀬戸内海: y }` か湾指定で書く
- 座標→海域は `src/lib/geo/sea-label.ts`（scripts/lib/sea-label-resolver.mjs と同期）

## 整合ルール（テストで機械検証）

- 適性0の地域には `fish-regional-seasons.ts` のシーズン定義を置かない
- 海水魚は lake/pond で地形0、淡水魚は海系spotTypeで地形0
- キーは実在する魚種slugのみ

## 検証・チューニング

- `node scripts/fish-aptitude-snapshot.mjs --label <名前>` で全魚種の件数・TOP30・
  tier分布・除外率を採取し、`--diff before.json after.json` で県×魚種ページの
  増減・除外率>40%の魚種（要レビュー）を検出する
- 過剰除外を避けるため excluded は保守的に（地域0/地形0/score<28 のみ）。
  疑わしきは fair（△まずまず）に倒す
